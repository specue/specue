Структура решений - набор полей (контекст, статус, обоснование и тд) определенных типов. Markdown не дает такой выразительности и правил. 

Структура хранится в CUE:
- Язык дает выражения как типов, так и значений как типы
- CUE достаточно выразителен для описания ограничений, строгих проверок
- Это позволяет переиспользовать схемы и значения
- Язык дает модульную систему и импорты схем

Отвергнуто:

- YAML-frontmatter — нет типов, валидации, импорта;
- JSON Schema — валидирует, но многословна и без модульности;
- plain JSON/YAML — данные без схемы;
- свой DSL — нужен парсер, валидатор, тулинг и обучение с нуля;
- Go DSL (схема в коде) — решения пишет автор, не Go-программист; смешивает
  схему с кодом, теряет декларативность;
- Dhall / Jsonnet — нишевее CUE либо слабее в типах и валидации.
</dec-body>
