Решение в своём
контракте ссылается на публичное поле контракта того решения, на которое
опирается и может выразить его через захват типов/значений, чтобы зафиксировать свои ожидания.

Контракты автора должен быть явно закрытым с помощью `close({...})`, тогда опирающиеся решения будут обязаны использовать только заявленные поля и типы. Это нужно так же делать для всех нижестоящих структур отдельно.

```cue
// решение выставляет основание
decision: s.#Decision & {
	problem: "Как хранить заказы"
	contract: close({
		// публичное основание для других
		storage: "postgres"
	})
}
```

```cue
// решение опирается на storage заказов
decision: s.#Decision & {
	problem: "Как делать бэкапы заказов"
	contract: close({
		// скрытая опора на чужое поле — ловится
		_storage: ordersDecision.contract.storage
	})
}
```

Для защиты нижестоящих полей, `close()` нужно проделать и на них.

```cue
contract: close({
	// на impact.dependent.breaks опираются -> 
	// dependent закрыт
	impact: {
		dependent: close({
			decision: string, 
			breaks: bool,
		})
	}
})
```

## Как фиксировать ожидания

Есть 2 типа фиксации ожиданий: 
- фиксация смысла (названия полей, схемы по сути)
- фиксация формы (типов, значений полей)

В CUE они выражаются по-разному:

| фиксация             | как ломается у соседа                     | где поймается                    |
| -------------------- | ----------------------------------------- | -------------------------------- |
| смысл (имя поля)     | поле исчезло -> `undefined field`         | если ЦЕЛЬ закрыта `close({...})` |
| форма (тип/значение) | поле стало другим -> `conflicting values` | в любом поле, даже скрытом       |

Смысл ловится через исчезновение, форма — через противоречие (`&`).

**Пример неправильной фиксации смысла** 

Цель не закрыта, переименование `storage` у соседа пройдёт молча:

```cue
// соседнее решение 
contract: {
	storage: "postgres"
}  // без close 

// молчит, если storage исчез
_storage: ordersDecision.contract.storage   
```

**Пример правильной фиксации смысла** 

Цель закрыта `close({...})`, исчезновение `storage` ловится даже в скрытом `_storage`:

```cue
// соседнее решение
contract: close({
	storage: "postgres",
})

// undefined field: storage
_storage: ordersDecision.contract.storage   
```

**Пример неправильной фиксации формы** 

Захвата нет, смена типа пройдёт молча:

```cue
// молчит, если port стал string
_port: ordersDecision.contract.port  
```

**Пример правильной фиксации формы** 

Захват через `&`, несовпадение даёт
противоречие (ловится даже в скрытом поле):

```cue
// conflicting int and string
_port: ordersDecision.contract.port & int  
```

Или, например, enum — фиксируем подмножество, расширение даёт противоречие:

```cue
// conflicting "json" and "xml", если добавили "xml"
_f: base.format & ("text" | "json")
```

А так же констрейнт — фиксируем границу, выпавшее значение ловится:

```cue
// invalid value 1 (out of bound >=3), если стало 1
_r: ordersDecision.contract.replicas & >=3
```

**Защита от поломок — это работа автора, а не безусловная гарантия CUE.**
