# Roadmap

Будущие доработки specue, отложенные намеренно.

## Обоснование решения (rationale) в модели

В модели `decisioning` обоснование выражено (`justifying-decision`: отвергнутые
варианты с причинами). В **specue** оно пока не доведено до схемы: у `#Decision`
нет поля обоснования, и доменной под-модели для него нет.

Открытый вопрос — где обоснованию место в трактовке specue:
- структурное поле в `#Decision` (как `status`/`links`);
- часть тела решения (README, проза);
- отдельный профиль (`reasoning`), подмешиваемый в `context`.

Пока убрано из доменной модели `internal/domain/decision-parts/*`, чтобы не
держать часть, на которую никто не опирается и которой нет в схеме. Вернуть,
когда решён вопрос места.

## Директория состояния инструмента

Состояние specue предполагалось хранить в системной директории пользователя
(XDG: `$XDG_STATE_HOME/specue`, по умолчанию `~/.local/state/specue`) — чтобы
вести решения из разных проектов и читать единое состояние при любом запуске.

Но инструмент состояние пока не ведёт: `specue add` только создаёт узлы, в
Go-коде нет ни state-директории, ни XDG. Решение `contract/state/state-directory`
было преждевременным — лист без потребителей в графе и без реализации.

Убрано из графа. Вернуть, когда у инструмента появится состояние, которое надо
где-то хранить.
