Проблема появляется из уже принятого решения.

После принятия решения, открывются новые вопросы "как" — это дочерние проблемы.

Пример:

Решение "Использовать Clean Architecture"
порождает проблемы:

- Как разделять слои?
- Как направлять зависимости между слоями?

Так решения и проблемы образуют цепочку: 

решение -> проблема -> решение -> ...

Проблема может не вытекать ни из какого решения. Такая проблема называется корневой.
