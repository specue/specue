Опора - то на чем решение держится над другими. Или то, чем одно решение держит другие. 

При изменении опоры, решения, которые на них опирались,
могут сломаться, поскольку у них не будет основания.

Опору можно выражаться в форме стабильного контракта, проверяемого машиной. 

Аналогией из программирования может служить сигнатура функции, API контракт.

В контракте нужно выражать публичную часть решения. Своего рода "обещания" для других решений о смысле или форме, объектов, которое определяет решение.

Все, что внутри решения может меняться часто и независимо от других решений - не должно попадать в контракт как основание. 

Пример в коде:

```go
// КОНТРАКТ (публичное) — основание для других. На это опираются.
type OrderStore interface {
    Save(o Order) error
    Get(id string) (Order, error)
}

// Реализация — приватные части, меняются свободно.
type pgStore struct {
    db       *sql.DB
    poolSize int    // было 10, стало 50 — никого не сломало
    table    string // переименовали orders -> orders_v2 — никого не сломало
}

func (s *pgStore) Save(o Order) error {
    // тело переписали с database/sql на pgx, добавили кэш — контракт цел
    ...
}
```

Другой код опирается на интерфейс `OrderStore`, а не на `pgStore`:

```go
// бэкап-сервис держится за контракт, не за реализацию
func Backup(store OrderStore) { ... }
```

Внутреннее (`poolSize`, `table`, тело `Save`, даже замена pgx на gorm)
меняется свободно — `Backup` цел. Сменишь сигнатуру `OrderStore` (уберёшь
метод, поменяешь тип) — сломаются все, кто на неё опирался.
